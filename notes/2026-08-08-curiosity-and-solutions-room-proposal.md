# Proposed: a "Curiosity Room" and a "Solutions Room" in Anansi, always connected, meant to keep the system dynamic through mutual capability improvement — not yet built, needs a definition decision

## Body

Abad proposed two new components inside Anansi: an "endless curiosity room" and a room with "an
extremely healthy obsession, a yearning for providing solutions to questions," directly connected
and forever interacting with each other. His stated purpose, in his own words, is "to improve and
evolve one another's capabilities and keep the system dynamic and ever evolving." No prior STAG
note, mandate, or spec uses this framing; a full search of the Knowledge Core and the repo root
found nothing under "curiosity room," "solutions room," or close variants, so this is a genuinely
new idea, not a restatement of an existing build.

REVIEW: high-impact. Before this can be built, one real ambiguity needs the operator's direct
answer, per Mandate 7 (no capability claim without proof): is each "room" a literal running
component (a scheduled agent, a background process, a folder structure with its own intake
pipeline) or a conceptual/governance framing for how existing research work (open questions feeding
solution-artifact work) should relate to each other. Building the wrong one wastes real
engineering effort and risks a false capability claim if a metaphor gets built as if it were a
system.
