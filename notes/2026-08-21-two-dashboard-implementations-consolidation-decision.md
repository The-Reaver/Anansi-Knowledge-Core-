# Decided to consolidate on the /dashboard/* route tree and delete a competing, thinner parallel dashboard implementation

## Body
While reconciling frontend TypeScript errors in `project_brief_step0_resolved`, the agent discovered the frontend contained two separate, competing dashboard implementations generated by different STAG tasks. "World B" was the complete implementation at `app/dashboard/` (with a shell layout, `page`, `billing`, `members`, `tools`, using `components/dashboard/*`, `lib/auth/roles`, `lib/api/billing`, `lib/api/toggles`). "World A" was a thinner, fragmentary duplicate covering the same billing and team-management functionality at different routes (`app/(dashboard)/billing`, a `billing-only` variant with no shared layout, `app/settings/team`), using separate thinner modules (`lib/roles`, a generic `lib/api.ts` client, `components/team/*`). World B already covered everything World A did, including handling the billing-only/suspended account state via a dedicated `SuspendedBillingOnly` component. Because consolidating meant removing user-facing URLs (`/billing`, `/settings/team`), the agent presented this as a decision for the operator rather than making it unilaterally, and the operator confirmed consolidating on `/dashboard/*`. World A's routes, components, and library modules were deleted, which also reduced the frontend's TypeScript error count by 18 for free. A second, similar duplication was found and removed shortly after inside "World B" itself: a broken parallel `/dashboard/tools` page using an entirely different, non-existent imagined API (`fetchToolTogglePageData`, `ToolState`, `PendingToggle`) that was not linked from navigation and had no other references, so it was deleted without needing a separate decision.

This is a narrow, project-specific product decision (which dashboard route tree to keep) rather than a broadly reusable engineering lesson on its own; it generalizes mainly in combination with the validator check note that turns this specific case into an automatic, reusable detection rule for future STAG builds.
